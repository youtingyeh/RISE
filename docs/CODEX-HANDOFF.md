## 已確定產品約束
- 完整保留 math、physics、chemistry 三學科；不可移除化學。教材內容由團隊維護。
- 原導覽要求：首頁、關於計畫、學生專區、助教專區、教師專區、核心團隊、重要日程、會員中心；管理員功能獨立且僅授權者可用。
- 使用者要求移除學生端學習路徑入口，保留科學探索；不要因舊文件而重新加回。
- 學生我的提問與問題草稿整合，完整填寫後可直接送出，保留圖片與思考歷程。
- 教師/助教待答工作台用於批閱學生問題；批閱三要素為思路分析、改進建議、延伸提問。
- 學生討論公告是選題後參與討論，不提供發布題目介面；不得將私有問答誤開放成公開討論。
- 作業依現有課程組下拉選擇指派對象；教師只能存取授權課程學生資料。管理員可審核也可主動授予課程權限。
- 教材管理屬教師與管理員；助教培訓課程建立限教師與管理員。
- 管理員功能包括會員姓名/角色管理、受控刪帳、資格審核、獨立影音管理頁、課程權限與功能開關。
- 保留助教認證、競賽、OER/年鑑、版本歷史及背景統計需求；不另製作顯性 KPI 儀表板。
- AI 顧問回饋包含假設檢查、概念重複、關聯強度；AI 外部依賴需另盤點。
- 上述為需求與決策，實際完成程度須讀碼並驗證。

## 最新部署決策
使用者確定未來採校內伺服器：
1. GitHub Pages 網頁遷至校內網頁伺服器。
2. Supabase 雲端資料庫、登入與附件服務改為自行管理；優先評估保留 Supabase 技術並自架，避免不必要重寫。
3. GitHub 可繼續版本管理；不需要為搬站刪除儲存庫。
4. 原 Google Drive／Storage 附件需盤點、搬移實體檔案、更新索引並保留私有存取。
5. 外部影片、SMTP、AI、CDN 等不因後端搬移就自動轉為本地，需逐項確認。
6. 校內 CPU/RAM/磁碟、OS、Docker 支援、網域、網路、SMTP、備份與維運窗口尚未提供。

## 首次接手任務
- 先唯讀盤點最新 branch、AGENTS.md、README、backend/、supabase/、tools/、tests/ 和 CI。
- 建立現況清單：哪些由程式確認、哪些需要正式環境核實。
- 檢查服務 URL、GitHub Pages /RISE/ 路徑、Auth callback/redirect、CORS、第三方 CDN 與附件 provider。
- 盤點 SQL 相依順序及明確 GRANT/RLS/RPC 權限；不假設雲端預設授權會存在於自架環境。
- 規劃校內測試環境、版本固定、設定範本、資料與 Auth 遷移、附件搬移、備份還原和切換/回復流程。
- 不把開發用 supabase start 直接公開為正式服務。
- 用測試資料驗證角色/課程隔離、登入與重設密碼、提交批閱、附件下載與刪帳流程。
- 依需求測試集中登入/交作業/觀看紀錄，區分註冊人數、同時上線與每秒請求；沒有實測就不承諾千人容量。
- 維持目前正式服務運作；未取得校內環境與明確切站授權前，不更改 DNS、不刪舊資料、不停用舊服務。
