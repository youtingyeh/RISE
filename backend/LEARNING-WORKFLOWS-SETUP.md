# 作業、培訓認證、競賽與學習成效：啟用步驟

這是可操作的第一版。沿用既有 RISE 帳號／角色與 Supabase，不依賴 AI 金鑰，也不用另部署 Edge Function。

## 一次安裝

1. 確認正在使用原本 RISE 的 Supabase 專案，已存在 `public.rise_profiles`。
2. SQL Editor → New query，貼上 `backend/learning-workflows.sql` **全文**並執行。此檔包含成對 `$$`，不要自行替換；可重複執行。
3. 成功後，用已驗證管理員帳號進入「管理員專區 → 管理工具」。可看到作業、培訓認證、競賽、學習成效四個入口。
4. 若出現「後端尚未安裝」，確認 SQL 在同一專案執行，並確認 GitHub Pages 已發布最新版本。

這份 SQL 建立 `rise_work` 私有資料表、三個公開 RPC 與 `rise-work-files` 私有附件區。網站不直接寫入私有資料表；每次 RPC 都依登入者即時身分檢查權限。
不修改既有帳號角色，不覆蓋 AI、Google Drive、原學生問答或教材資料。

## 可以開始使用的流程

### 作業修改歷程與結構化批閱

- 教師／管理員在 `assignments.html` 建立作業，填學科、要求、截止時間（可不設）並發布。
- 學生從「學生專區 → 我的作業」選作業，輸入推理並上傳最多三份 PDF／JPG／PNG／WebP，各 5 MB。
- 教師／助教可查看學生各版本，填「思路分析、改進建議、延伸提問」，選擇 0–4 級推理表現及「請修訂／完成」。
- 學生再次提交時必須填修改說明，建立新版本；舊版本、附件與批閱不覆寫。可選是否保留上一版附件。
- 每位評閱者每一版只提交一次評語；另一位教學人員可補充批閱。最新版本的最近一次評語決定目前完成狀態。
- 截止／關閉後禁止提交；教師若需要繼續收件，建立作業時可不設截止時間，使用關閉／重新開放控制。第一版不提供修改既有固定截止日期。

### 助教培訓認證

- 管理員在 `ta-training.html` 建立課程。表單提供一份可編修的試用考核範本，包含教學溝通、錯誤診斷、標準批閱、回饋倫理；請確認內容後發布。
- 教師／助教閱讀並提交考核成果；管理員可退回補件，申請人再交新版本。
- 管理員依最新成果核發一年期的「平台內部培訓認證」，可撤銷；申請人可下載認證文字紀錄。
- 認證不等於學位、國家專業證照，也不會自動授予教師／助教帳號權限。原資格審核仍分開運作。
- 第一版採人工考核，沒有自動測驗、題庫計分或第三方公開驗證網址。下載檔案的有效性以登入後當前認證紀錄為準。

### 提問競賽

- 教師／管理員在 `competitions.html` 建立競賽草稿、辦法、截止時間；填明資格、四項評量標準及結果公開範圍。
- 主辦教師／管理員指定已驗證教師／管理員為評審，再開放投稿。
- 學生與助教可選高中／大專、自然科學／人文／社會／跨領域，提交問題與背景、動機、可能影響。組別資格由主辦人依辦法人工確認。
- 截止前可更新作品，保留版本；截止後主辦人切換「評審中」，僅最後一版進入評審。
- 評審介面隱藏投稿帳號，但作品中的姓名無法自動去除。參賽者須移除識別資料；有指導或其他利益衝突時，評審先停止評分並通知主辦人。
- 主辦人可更換尚未評分的評審；已有評分者不能移除。四項分別為創新性、深度、適切性、啟發性，各 0–5 分，需文字理由。
- 全部作品完成指定評審後，主辦人才可發布結果。結果顯示分組、作品標題、平均總分／20 與評審數，不公開帳號、完整投稿或私人評語；參賽者可查看自己評語。
- 第一版不自動判定獎項、不寄送競賽通知、不提供申覆／撤回／資格初審表單。需補件或取消參賽時由主辦人先人工處理，不要直接重開評分流程。

### 學習成效

- 學生只看本人；教學人員可查看已繳交作業的學生。
- 顯示繳交作業數、版本數、修訂數、完成數、最新版本待批閱數，以及每一版本的推理表現與評語結果。
- 另提供已批閱版本、培訓提交版本、有效認證與競賽投稿數彙整。
- 可下載作業彙整 CSV。未繳交者不在作業表內，不把登入或觀看次數當成學習效果。
- 這是描述性統計，尚不涵蓋錯誤分類、跨年度能力成長推估、個人化練習推薦或完整研究報告。

## 權限摘要

| 功能 | 學生 | 助教 | 教師 | 管理員 |

| 作業繳交／修訂 | 本人 | — | — | — |
| 作業批閱 | — | 可 | 可 | 可 |
| 建立／發布作業 | — | — | 自己建立的 | 全部 |
| 培訓成果 | — | 本人 | 本人 | 審核 |
| 培訓課程／認證管理 | — | — | — | 可 |
| 競賽投稿 | 本人 | 本人 | — | — |
| 競賽管理 | — | — | 自己建立的 | 全部 |
| 競賽評分 | — | — | 被指定才可 | 被指定才可 |

所有操作均須登入且信箱已驗證。網站隱藏按鈕之外，後端亦檢查角色；不能透過自行呼叫 RPC 取得較高權限。

## 正式使用前驗收

使用專用測試帳號，依序走過：

1. 教師發布作業 → 學生交第一版 → 助教三欄批閱 → 學生交第二版 → 教師標示完成 → 學生回看兩版 → 成效頁顯示一份作業、兩版、一次修訂。
2. 管理員發布培訓 → 助教提交 → 退回 → 助教修訂 → 核發 → 撤銷 → 原認證不再顯示有效。
3. 主辦建立競賽 → 指定評審 → 學生投稿及修訂 → 截止後評審 → 全部評完才能發布 → 參賽者僅看自己的評語。
4. 另一位學生不能取得他人作業、培訓成果、競賽原文或未發布評語；未指定教師不能評分。

本次自動測試採 PGlite 與 DOM 模擬，涵蓋上述核心流程、RLS/RPC 權限、過期版本與截止限制。未自動連接正式 Supabase；安裝 SQL 後仍應完成真人帳號驗收。

## 維運界線

- 第一版以小規模試用為目標，清單與歷程尚未加入伺服器分頁；大量資料上線前應補分頁與分班／指派範圍。
- 作業附件保留供歷史版本查看，不提供直接覆寫／刪除。未成功提交的已上傳附件也保留，避免重試誤刪；維運端需定期檢查未引用附件。
- 刪除學生 Auth 帳號會連帶移除其作業／培訓／競賽紀錄；教學人員刪帳保留教學內容與評語但清空作者關聯。附件實體清理仍需透過 Storage API 納入既有刪帳流程，不可只刪 storage.objects。
- 不在正式帳號／學生資料上測試刪帳。既有 admin-console.sql 的刪帳與附件清理另有先前報告所列問題，本次未重寫該流程。
