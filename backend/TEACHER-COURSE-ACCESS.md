# 教師課程權限更新

在 Supabase SQL Editor 執行 `backend/teacher-course-access.sql` 全文。既有站台須已安裝 `setup.sql`、`staff-upgrade.sql`、`qa-upgrade.sql`、`course-assignments.sql`、`training-course-management.sql`。本次不必重跑那些舊檔；若日後重跑舊的 workflow migration，請最後再執行本檔。

執行後：

1. 管理員前往「管理員專區 → 教師課程權限」。
2. 為每位既有教師指定課程，或核准全部課程；未設定者預設沒有其他學生資料的查看權限。
3. 新教師在資格申請時選擇任教課程或申請全部課程。管理員在資格審核頁確認實際核准範圍，可以與申請範圍不同。
4. 教師／管理員在「學習成效」以課程下拉選單篩選；學生與助教的成效頁只顯示本人。

權限涵蓋成效查詢與 CSV 使用的資料、學生名單搜尋、作業指派、作業歷程及批閱、作業附件、學生私有問答與圖片。管理員保留全部權限。現有助教的協助問答／批閱權限維持原設定，這次未建立助教的課程授權機制。公開教材、共享討論公告、競賽公開結果與指定評審流程不是私有學生成效，維持原有規則。

課程名單採用學生目前加入的課程。退出課程會移除教師對該生的課程存取，但不刪除歷史紀錄。學生同時加入多門課，不會因此把另一門課的作業開放給未授權教師。全部學生／個別學生作業不具有單一課程歸屬，依目前學員名單納入；同一學生跨課程時，各課統計可能重疊，不能相加當作全站人數。

統計只計入已提交作業的學生；未提交學生可由課程指派名單另行查看，不將「沒有紀錄」推論為學習能力不足。培訓與競賽沒有學生課程歸屬，因此不在教師課程統計中顯示其全站總數。

更改帳號角色會清除原教師課程授權；再次升為教師時需重新核准。授權異動記錄保存在私有 `rise_work.teacher_access_log`。已下載的檔案或尚未到期的短效簽名連結無法收回。

本更新不刪除既有作業、申請或學習紀錄。未執行新版 SQL 時，前端成效頁會提示安裝，避免誤顯示舊版全站資料。
